API docs by Redocly Disperso API ( 1.0.0 ) Download OpenAPI specification : Download E-mail : contacto@disperso.com Terms of Service Introduction Welcome to the Disperso REST API reference. Here you will find the details of every endpoint to create and query payment orders to beneficiaries in Chile, Peru and Mexico. Base URL All endpoints are available under https://api.disperso.com . This URL is the same for the production and sandbox environments; the environment is determined solely by the authentication token. Authentication Every request must include your token in the X-Disperso-Access-Token header. Use a pk_live_XXXXXX token for production and a pk_sandbox_XXXXXX token for the test environment. Integration guide For the full guide —payment flow, status handling, polling loop and per-country test data— see the integration guide . Ordenes de pago Operaciones relacionadas con la creación y consulta de órdenes de pago a través de la API Create a payment order via API for Chile Creates a payment order through the API. This operation creates a payment order by sending the access token and the data required for the order. Remember that, to create a payment order in the sandbox environment, you must first obtain the access token for that environment. Possible responses with HTTP 200: This endpoint can return two types of successful response under the same HTTP 200 code, depending on whether the bank responded within the time limit or not. Transfer processed: The order was created and the bank confirmed the transfer immediately. The status field returns DONE and bankTransferInfo[].status returns BANK_TRANSFER_DONE . In this case the response includes the paymentOrderId generated by the system, the amount detail, the commission and the transfer date. Time-out (payment processing): The bank did not respond within the established time limit. In this case the system returns immediately with status: BANK_PROCESSING and the clientPaymentId sent in the request. This does not indicate an error or a rejection - it means the payment was received and is still being processed in the background. To find out the final result, you must query the payment status afterwards using one of these endpoints: GET /api/v1/payment-order/internal-id/{clientPaymentId} - using your own internal identifier. GET /api/v1/payment-order/{paymentOrderId} - if you already obtained the ID from our system.
